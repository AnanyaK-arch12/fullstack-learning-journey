# Week 1: Introduction to Full-Stack Development

## 1. Introduction to Full-Stack Development

Full-stack development involves developing both the frontend and backend of web applications.

### Concepts Learned

- **Frontend:** The user interface of a website that users interact with.
- **Backend:** The server-side part that handles application logic and processes requests.
- **Database:** Stores, organizes, and manages application data.
- **API:** Enables communication between different software applications.
- **Client-Server Architecture:** A model where the client sends requests and the server processes them and sends responses.

### How Full-Stack Development Works

- The frontend sends requests to the backend.
- The backend processes requests and interacts with the database when needed.
- The backend sends responses to the frontend.
- The frontend displays the results to the user.

## 2. Introduction to Git

Git is a distributed version control system that helps developers track changes in their code and manage different versions of a project.

### Concepts Learned

- **Version Control:** Tracks changes made to files over time.
- **Repository:** Stores project files and their version history.
- **Commit:** Saves a snapshot of changes.
- **Branch:** Provides an independent line of development.
- **Working Directory:** The folder containing the current project files.
- **Staging Area:** Holds changes selected for the next commit.

### Basic Git Commands

| Command | Description |
|---|---|
| `git init` | Initializes a new Git repository |
| `git status` | Checks the status of files |
| `git add .` | Stages all changes |
| `git commit -m "message"` | Commits staged changes |
| `git log` | Displays commit history |
| `git branch` | Lists or manages branches |

## 3. Introduction to GitHub

GitHub is a cloud-based platform used to host Git repositories, collaborate on projects, and contribute to open-source software.

### Concepts Learned

- **Remote Repository:** A repository hosted on GitHub or another remote platform.
- **Push:** Uploads local commits to a remote repository.
- **Pull:** Fetches and integrates changes from a remote repository.
- **Clone:** Creates a local copy of a remote repository.
- **README.md:** Provides information about a repository, including its purpose and contents.
- **Open Source:** Software whose source code is publicly available under a license that permits specified forms of use and contribution.

### Basic Git and GitHub Workflow

1. Create a project folder.
2. Initialize Git using `git init`.
3. Stage changes using `git add`.
4. Commit changes using `git commit`.
5. Create a repository on GitHub.
6. Connect the local repository to GitHub.
7. Push commits to the remote repository.
